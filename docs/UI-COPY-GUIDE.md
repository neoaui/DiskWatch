# DiskWatch2 界面文案规范

参考火绒安全、Windows「设置 → 存储」、LightC 模块页、WizTree / TreeSize 等常见系统工具的写法，整理如下。以后改界面说明都按这套来。

## 依据（摘要）

- **火绒**：功能名是短名词（垃圾清理、隔离区、信任区）。说明一句话说清对用户的作用，例如「针对这些敏感位置进行快速的查杀，用时较少」。设置项写结果，不写引擎原理。会删除或不可恢复时，才写清后果。
- **Windows 存储**：分类名直接、克制（已安装的应用、临时文件、系统和其他保留的空间）。副标题说明能看到什么，不解释统计方法。
- **LightC**：模块名同样短（垃圾清理、大文件清理、磁盘变化分析）。安全等级用短标签。实现细节不出现在标题里；风险说明放在真正要操作之前。
- **WizTree / TreeSize**：列表和状态以数据为主，说明极短。专业词（如分配大小）若必须出现，用一句人话解释，而不是展开实现。

## 规则

1. **标题用短名词或动宾短语。** 如「应用排行」「瘦身建议」「塞满预测」。不要在标题里写实现方式。
2. **副标题只写用户能看到什么，一句说完。** 不写算法、规则表、数据如何归组。
3. **不用口语和对话口吻。** 避免「谁在吃」「看看」「你的磁盘」「不用等」，也不用「我们」。用陈述句。
4. **主界面不出现实现词。** 如 FRN、MFT、USN、规则表、口径、统计桶、settings.json。必要时放到提示或「名词说明」。
5. **「不会删除任何文件」这类保证，只出现在会删除、移动或导出可执行建议的地方。** 浏览、对比、排行等只读页面不再重复强调。
6. **标点统一。** 用句号、逗号、顿号；不要用一长串「 · 」把多句话串在一起。数字与单位之间留空格，如 18.72 GiB。
7. **空状态固定两行：先说缺什么，再说可以怎么做。** 例如「还没有扫描结果。点击右上角「开始扫描」。」
8. **设置项：名称写功能，下一行帮助写清适用条件和后果，不写实现步骤。**
9. **进度和状态只报当前在做什么、完成了多少，不夹带原理说明。**
10. **导出给 AI 的安全规则可以稍长，但语气是条款，不是聊天。** 关键约束原意不变：每步先确认、转移前检查目标盘空间、标红或列入不可删除的文件一律不碰。

## 保留用语

以下名称和口径不改：隐性占用空间 / 未解释差额、瘦身建议、导出 AI 提示词、五类增长分级（显著增长、快速增长、轻微增长、新增、以及不可删除的红/橙/黄标记）、提醒档位 20 / 11 / 3 GiB。
